# Security policy

## Supported code

Security fixes target the current code on `main` and the portfolio at
[khaledsaeed.tech](https://khaledsaeed.tech). Older commits and forks are not maintained
separately. Owners of reused copies are responsible for applying upstream fixes and securing
their own deployments.

## Report privately

Email [contact@khaledsaeed.tech](mailto:contact@khaledsaeed.tech) with the subject
`[Portfolio security]` and a description of the concern. Do not publish vulnerability details,
exploit code, credentials, or private information in an issue or pull request.

Include what you can:

- Affected URL, component, dependency, or commit.
- Reproduction steps and a minimal proof of concept using non-sensitive data.
- Potential impact and any conditions needed to exploit the issue.
- Browser and environment details, where relevant.
- A suggested fix or mitigation, if available.

If you are unsure whether a problem is security-related, use this private contact. Ordinary
display bugs, broken links, and accessibility problems belong in the public issue tracker.

The maintainer will assess the report and coordinate next steps and disclosure with you.
Response and resolution times depend on availability; there is no guaranteed service level.
If you have not received a response, follow up in the same email thread. Please allow time
for assessment and a fix before disclosing details publicly.

Keep testing limited to the minimum needed to demonstrate an issue. Do not access other
people's data, disrupt the live site, or test third-party services through this policy.
